# Positioning and visual system

Category: **evidence-based agent memory**.

One sentence: UniMem gives agents persistent memory and connects its use to outcome evidence and governed change.

Selected hero: **Memory should earn your agent’s trust.**

Audience priority: AI infrastructure teams and AI-native builders first, enterprise operators second; developers, integration partners, and investors can follow the same story.

## Headline exploration

Ten alternatives were evaluated against clarity, source support, memorability, and the risk of implying that useful evidence establishes truth:

1. Memory should earn your agent’s trust. — selected; requires the concrete subheading and governance qualification.
2. Give agents experience with evidence.
3. Remember what helps. Reconsider what doesn’t.
4. A better memory starts with a better question.
5. Find out what your agent should remember.
6. Make the next task inherit the lesson.
7. Persistent memory. Accountable change.
8. Put remembered experience to the test.
9. Your agent remembers. What changed?
10. Keep the lesson. Measure the difference.
11. Build a memory loop you can inspect.
12. Experience should have a future.

Avoid unconditional “learns automatically,” “guarantees better outcomes,” and “only memory system with governance.” Product responsibility is distinct from competitors’ implementation details.

## Visual direction

An editorial technical notebook: generous space, compact numbered rails, structured horizontal rules, strong typography, and one evidence graph. No stock imagery, brains, glowing spheres, customer logos, or fabricated console imagery.

| Token          | Value / use                                                                        |
| -------------- | ---------------------------------------------------------------------------------- |
| Paper          | `#f8f9f5` background, `#ffffff` panels                                             |
| Ink            | `#20251c` text and primary actions                                                 |
| Secondary      | `#646b5f` body supporting text                                                     |
| Accent         | `#d6f78b` trust underline, active details, dark-section symbols                    |
| Evidence green | `#47682b` active controls and measured-help cues                                   |
| Rules          | `#dce0d5`                                                                          |
| Typeface       | Self-hosted variable Geist, OFL license retained; approximately 31 KB WOFF2 subset |
| Code           | System monospace; contrasting comments and commands on dark olive                  |
| Spacing        | 4/8 px baseline; section space 66 mobile / 110 desktop                             |
| Radius         | 3–5 px controls and surfaces; circles only for nodes and next controls             |
| Icons          | Simple authored SVG lines and a linked-path monogram                               |
| Motion         | Short color/hover transitions; no autoplay; reduced-motion override                |

Signature visual: an explicitly illustrative memory loop with stable memory IDs, delivery/withholding marks, real implementation verdict names, and configured withdrawal. Five keyboard-operable controls expose the explanation. Synthetic outcomes never resemble customer evidence. Supporting product copy is available in rendered HTML without advancing the interaction.

The hero and below-fold structure were inspected in Chromium on desktop and mobile. Screenshots and actual validation outcomes are described in `qa.md`.
